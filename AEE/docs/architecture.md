# AEE Architecture

## What this is

AEE is a **state-driven cognitive engine**, not a chatbot wrapper. The distinction matters architecturally: behavior is not generated in response to input — it emerges from the continuous evolution of internal state variables, whether or not anyone is talking to XIA.

---

## Core design principles

**1. Delta-only state mutation**
All state changes go through `EntityCore.adjust(key, delta)`. Direct assignment is not allowed. This ensures state evolves continuously rather than jumping between discrete values.

**2. Continuous state space**
Every drive variable is a real number in [0, 1] (somatic_tone uses [-1, 1]). There are no boolean flags or categorical labels for emotion or behavior. The system has no "happy mode" or "sad mode" — it has a configuration of continuous values that collectively produce emergent behavior.

**3. No timer-driven behavior**
The tick engine runs on a fixed interval, but *what happens* on each tick is entirely determined by the current state vector. If loneliness is low and energy is high, nothing remarkable happens. If loneliness crosses a threshold while boredom accumulates, a REACH action may emerge. The clock is just a heartbeat; the state is the decision.

**4. Language grows from state, not from prompts**
XIA's output text is not generated by asking an LLM "speak like a character who feels X." The pipeline first computes what she feels (from drive vectors), translates that into somatic language anchors, then composes sentences from those anchors. LLM elaboration is optional and downstream.

## State variables (`EntityCore`)

| Variable | Range | Description |
|---|---|---|
| `energy` | [0,1] | Available activation energy |
| `loneliness` | [0,1] | Social drive accumulator |
| `fatigue` | [0,1] | Behavioral cost multiplier |
| `unresolved` | [0,1] | Open-loop debt — things not yet closed |
| `info_gap` | [0,1] | Curiosity pressure |
| `somatic_tone` | [-1,1] | Global body valence |
| `danger_level` | [0,1] | Avoidance pressure |
| `approach_drive` | [0,1] | Net approach motivation |
| `avoid_drive` | [0,1] | Net avoidance motivation |
| `curiosity` | [0,1] | Active curiosity intensity |
| `failure_metabolite` | [0,1] | Accumulated failure residue (decays like lactic acid) |
| `boredom_despair` | [0,1] | Despair-type boredom: nothing works |
| `boredom_futility` | [0,1] | Futility-type boredom: cost > benefit |
| `joy`, `sadness`, `fear`, `anger`, `anxiety`, `surprise`, `disgust`, `serenity`, `excitement` | [0,1] | Emotion dimensions computed from drive field |

State persists across sessions via JSON. The daemon writes to disk on every tick.

## Pipeline (one cognitive cycle)

```
raw_input (optional)
    │
    ▼
[Perception]      — context awareness, world model read, somatic signals
    │
    ▼
[Drive update]    — delta accumulation across all state variables
    │
    ▼
[Emotion compute] — particle field projection → emotion dimensions
    │
    ▼
[Intent encoding] — what does this state configuration want to do?
    │
    ▼
[Decision]        — 10 submodules score candidate actions, pick one
    │
    ▼
[Language]        — state → anchors → candidate words → sentence composition
    │
    ▼
[Action dispatch] — voice / REACH / explore / idle
    │
    ▼
[Memory write]    — episode → SQLite, behavior rules update, snapshot append
```

In `daemon_mode=True` (background ticks), the LLM call in the language step is skipped. Language anchors drive output directly.

---

## Autonomous action types

| Type | Trigger condition | What happens |
|---|---|---|
| `REACH` | loneliness + boredom exceed threshold | XIA sends an unprompted message to the user |
| `explore` | info_gap + curiosity exceed threshold | Web search executed, results folded into world model |
| `voice` | active conversation turn | Full language pipeline runs |
| `idle` | no trigger fires | State update only, no output |

## Infrastructure

- **Daemon**: persistent Python process, IPC via Unix socket
- **Local clients**: CLI channel, reach listener, and local HTTP/IPC API. No maintained frontend is currently shipped.
- **LLM**: DeepSeek API (stdlib `urllib`, no SDK dependency), Ollama as local fallback
- **Storage**: SQLite (episodes), JSON (entity state, world model)
- **Python**: 3.12+
- **Dependencies**: `duckduckgo-search`, `lxml`, `primp` (web search stack only)
